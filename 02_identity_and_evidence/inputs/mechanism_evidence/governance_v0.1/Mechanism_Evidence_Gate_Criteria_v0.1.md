# Gate验收标准 v0.1

2026-10-21。CRITERIA_PROPOSAL / HUMAN_DECISION_REQUIRED。标准提出不等于当前Gate已通过。Gate决定须附版本、对象范围、审核者、证据链接、未决事项与签署日期，不能只有一个PASS文字。

## Gate 1：结构与技术完整性

| ID | 必须满足 | 验收证据 | 未满足处理 |
|---|---|---|---|
| G1-01 | schema/词表/缺失规则获项目批准，字段定义全覆盖且类型明确 | 已签规则、字段映射与版本 | HOLD，技术QC不能代签 |
| G1-02 | 稳定PK唯一、外键存在、legacy映射可追踪 | 重复/孤立/循环检查报告 | 不导入生产 |
| G1-03 | 每观察有候选、主出处、设计、endpoint、比较与来源定位；未知值有原因 | 条件必填检查；可空值不伪造 | 暂存隔离，必要FK缺失为失败 |
| G1-04 | dose值/单位/基准及时间角色分开，无错误0填补 | 单位/枚举/范围检查及代表样例人工检查 | 修订后重验 |
| G1-05 | 观察/实验/材料/出版物不混计，样本单位明确或未决 | ER/独立性检查 | 可保留未决，但不能独立性分析 |
| G1-06 | 迁移前后记录、ID、原始值和审核历史可对账；无越权批准 | dry-run差异、回滚及批准事件核验 | 不应用迁移 |
| G1-07 | 既有保护资产SHA256不变，或另有获批变更请求 | 前后manifest及批准范围 | 停止并查差异 |
| G1-08 | 程序QC通过并由技术责任人签署范围/版本 | 可复现检查与签署 | HOLD |

未知生物学内容可以在明确缺失规则下通过结构检查；这不意味着科学证据充分。G1不得为了PASS把未知填零、猜测ID或宣称FULL_TEXT_VERIFIED。当前只完成治理文档QC，不是未来生产schema的G1演练。建议当前Gate1=HOLD，等待规则批准及独立实施任务。

## Gate 2：科学审查与有效子集

| ID | 必须满足 | 最低审核要求 |
|---|---|---|
| G2-01 | 化合物参考身份和实验形式关系合理 | 不把母体CID当样品鉴定，衍生物单独处理 |
| G2-02 | 文献身份、来源版本及动态状态可靠 | DOI/PMID指向文章自身；记录更正/关注/撤稿检查日期 |
| G2-03 | 模型、试剂对象、剂量基准、时间及对照可追溯 | 核方法、结果、对应图表；未报/冲突明确保留 |
| G2-04 | 三个分类维度不越界 | 不借其他行升级，不把药理/表达/对接作直接靶点 |
| G2-05 | 阴性、促氧化及真实非抗氧化结果完整保留 | 方向和显著性分开；不以研究偏好排除 |
| G2-06 | 来源冲突定位明确并隔离受影响断言 | 文本/图/补充分范围；无合法全文不冒称验证 |
| G2-07 | 具名人工对指定record_version/字段范围作决定 | Review_Event中decision、理由、来源与approval均可核查 |
| G2-08 | 已验证导出集合由适配过滤器构建 | 逐行审核、科学类型、来源完整性及无开放关键HOLD同时满足 |

可将“某版本的已审子集满足Gate2”与“登记库仍有HOLD”并存，但必须报告分母/排除原因/适用断言，不宣布整个库全通过。HOLD仍可存在于暂存主存储和来源登记，不得进入 verified_direct_targets、verified_antioxidant_mechanisms、独立支持计数、正式评分/训练/排名或无区分的有效证据总数。公开治理附件若需展示HOLD必须单独标识并经发布授权，不得作为验证证据包。

verified_direct_targets要求人审批准该版本及具体蛋白身份/结合断言、target_confirmation_class=DIRECT_BINDING_SUPPORTED、相关方法结果来源核查完成、关键对象/控制无未决冲突。verified_antioxidant_mechanisms要求人审批准具体机制链与模型，具有可定位红氧结局及功能支持；只有DIRECT_REDOX_OUTCOME、蛋白名称或作者声称机制不充分。人审批准的其他功能、组学、计算观察可进入各自已审类型视图，但不能跨视图升级。HUMAN_APPROVED也不自动满足所有用途：批准范围、source issue和publication有效性须同时检查。

当前21条均未人工批准；12 KEEP_PROVISIONAL、2 RECLASSIFICATION_PROPOSED、7 HOLD_SOURCE_VERIFICATION为Codex建议，不是这里的数据审核状态枚举。建议Gate2=HUMAN_SCIENTIFIC_REVIEW_REQUIRED。来源HOLD不强制删除，TRAF2和amylase开放问题没有被治理规则关闭。

## Scale-up：四种独立权限

| 权限 | 正式准入条件（全部满足） | 当前建议 |
|---|---|---|
| S1 收集下一批暂定证据 | 治理/schema/责任获批；Gate1在隔离试点演练通过；现21条分类边界已有人审校准；关键HOLD隔离策略获批；指定候选清单/批次上限/检索式与截止时间/停止条件/人员容量；研究负责人明确授权 | HOLD / NOT_AUTHORIZED |
| S2 纳入已审主表 | S1合规来源记录；每新行通过G1/G2及版本化人工批准；身份与来源关键HOLD清除；不把provisional整批改为approved | HOLD / NOT_AUTHORIZED |
| S3 分析或排名 | 单独批准研究问题、纳排与分析方案；冻结适用证据版本；复用/聚类/缺失及多重性处理可审计；仅适配已审集合；计算预测与实验、红氧与其他作用不混分；Frozen变更另走CR | HOLD / NOT_AUTHORIZED |
| S4 正式发布 | 发布范围及版本获批；全部导出与批准范围一致；许可/再分发审查；来源和变更日志/机器可读字典/完整性清单/可复现导出QC；负责人签署发布 | HOLD / NOT_AUTHORIZED |

S1可在明确隔离且不影响分类政策的历史HOLD仍存在时，申请有限下一批收集；这不要求强行补完全部原儿茶酸发现文献。但不允许绕过未定规则直接铺开191个候选；若未决问题阻止通用分类边界则S1继续HOLD。S2不是S3的自动许可，S3不是S4的自动许可，S4可发布明确分层的登记信息而不宣称所有观察已验证；具体发布子集仍需审批。任何权限只对签署批次/版本有效。

停机条件：系统性身份/单位/来源错误、未审证据进入已审集合、冻结资产意外变化、审核容量不足、超过授权候选范围或发现新关键来源冲突时暂停对应流程并记录事件。技术维护者不能借S1授权更新Frozen Top20、157×5矩阵或运行网络医学算法。
